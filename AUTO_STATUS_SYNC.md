# Автоматическая синхронизация статусов спринта и задач

## Описание функциональности

Реализована автоматическая двусторонняя синхронизация статусов между спринтами и их задачами.

## Как это работает

### Автоматический пересчет статуса спринта

Статус спринта автоматически пересчитывается при следующих операциях с задачами:

1. **Создание задачи** (`POST /api/tasks`)
2. **Отправка задачи на рассмотрение** (`PATCH /api/tasks/{id}/submit`)
3. **Одобрение задачи** (`PATCH /api/tasks/{id}/approve`)
4. **Отклонение задачи** (`PATCH /api/tasks/{id}/reject`)
5. **Удаление задачи** (`DELETE /api/tasks/{id}`)

### Логика определения статуса спринта

Статус спринта определяется на основе статусов всех его задач:

| Условие | Статус спринта |
|---------|----------------|
| Все задачи имеют статус APPROVED | **APPROVED** |
| Хотя бы одна задача имеет статус REJECTED | **REJECTED** |
| Хотя бы одна задача имеет статус ON_REVIEW (и нет REJECTED) | **ON_REVIEW** |
| Все задачи имеют статус CREATED | **CREATED** |
| В спринте нет задач | **CREATED** |

### Приоритет статусов

При наличии задач с разными статусами применяется следующий приоритет:

1. **APPROVED** - только если все задачи одобрены
2. **REJECTED** - если есть хотя бы одна отклоненная задача
3. **ON_REVIEW** - если есть задачи на рассмотрении (и нет отклоненных)
4. **CREATED** - если все задачи только созданы

## Новый API endpoint

Добавлен новый endpoint для ручного пересчета статуса спринта:

```
PATCH /api/sprints/{id}/recalculate-status
```

Этот endpoint можно использовать для принудительного пересчета статуса спринта на основе текущих статусов задач.

## Примеры использования

### Сценарий 1: Все задачи одобрены

```
Спринт: CREATED
Задача 1: CREATED → ON_REVIEW → APPROVED
Задача 2: CREATED → ON_REVIEW → APPROVED

Результат: Спринт автоматически → APPROVED
```

### Сценарий 2: Одна задача отклонена

```
Спринт: APPROVED
Задача 1: APPROVED
Задача 2: APPROVED → REJECTED (изменили статус)

Результат: Спринт автоматически → REJECTED
```

### Сценарий 3: Задача отправлена на доработку

```
Спринт: APPROVED
Задача 1: APPROVED
Задача 2: APPROVED → ON_REVIEW (вернули на доработку)

Результат: Спринт автоматически → ON_REVIEW
```

### Сценарий 4: Удаление задачи

```
Спринт: APPROVED
Задача 1: APPROVED
Задача 2: APPROVED → DELETED

Результат: Спринт остается APPROVED (так как оставшаяся задача одобрена)
```

## Технические детали

### Измененные файлы

#### Sprint Service

1. **SprintService.java**
   - Добавлен метод `recalculateSprintStatus(Long id)` для пересчета статуса

2. **SprintController.java**
   - Добавлен endpoint `PATCH /{id}/recalculate-status`

#### Task Service

1. **TaskService.java**
   - Добавлен метод `recalculateSprintStatus(Long sprintId)` для вызова sprint-service
   - Обновлены методы:
     - `createTask()` - вызывает пересчет после создания
     - `submitForReview()` - вызывает пересчет после отправки на рассмотрение
     - `approveTask()` - вызывает пересчет после одобрения
     - `rejectTask()` - вызывает пересчет после отклонения
     - `deleteTask()` - вызывает пересчет после удаления

2. **SprintServiceClient.java**
   - Добавлен метод `recalculateSprintStatus(Long id)` для вызова нового endpoint

### Межсервисное взаимодействие

```
Task Service → Feign Client → Sprint Service
     ↓
recalculateSprintStatus()
     ↓
GET /api/sprints/{id}/tasks
     ↓
Анализ статусов задач
     ↓
Обновление статуса спринта
```

## Логирование

Система логирует все автоматические изменения статусов:

```
INFO: Sprint 123 status automatically changed from CREATED to ON_REVIEW
INFO: Sprint 123 status recalculated based on tasks
ERROR: Failed to recalculate sprint 123 status: [error message]
```

## Обработка ошибок

- Если не удается связаться со sprint-service, ошибка логируется, но операция с задачей не откатывается
- Это гарантирует, что проблемы с синхронизацией не блокируют основные операции
- Статус можно пересчитать вручную через endpoint `/recalculate-status`

## Совместимость

Изменения полностью обратно совместимы:
- Существующие endpoint'ы работают без изменений
- Добавлен только новый endpoint для ручного пересчета
- Автоматическая синхронизация работает прозрачно для клиентов API
