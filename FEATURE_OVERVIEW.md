# Обзор функционала: Комментарии к артефактам

## Визуальная схема

```
Задача
├── Общие комментарии (к задаче)
│   └── Комментарий 1
│   └── Комментарий 2
│
└── Артефакты
    ├── Артефакт 1: "Дизайн макет.pdf"
    │   ├── 💬 3 комментария
    │   │   ├── "Отличный дизайн!"
    │   │   ├── "Нужно изменить цвет кнопки"
    │   │   └── "Исправлено ✓"
    │
    ├── Артефакт 2: "API документация.docx"
    │   ├── 💬 1 комментарий
    │   │   └── "Добавить примеры запросов"
    │
    └── Артефакт 3: "Скриншот бага.png"
        └── 💬 0 комментариев
```

## Как это работает

### До обновления
```
❌ Комментарии только к задаче в целом
❌ Непонятно, к какому файлу относится комментарий
❌ Нужно писать "По файлу design.pdf: ..."
```

### После обновления
```
✅ Комментарии привязаны к конкретному артефакту
✅ Видно количество комментариев у каждого файла
✅ Удобная навигация и контекст
```

## Пример использования

### Сценарий 1: Ревью дизайна

1. Дизайнер загружает макет как артефакт
2. Тимлид открывает задачу
3. Нажимает на счетчик комментариев у макета
4. Пишет: "Изменить цвет кнопки на #FF5733"
5. Дизайнер видит комментарий прямо под файлом
6. Загружает исправленную версию
7. Отвечает: "Исправлено ✓"

### Сценарий 2: Код ревью

1. Разработчик прикрепляет скриншот кода
2. Ревьювер комментирует: "Использовать async/await"
3. Разработчик прикрепляет новый скриншот
4. Комментирует: "Переделано"

### Сценарий 3: Баг репорт

1. Тестировщик прикрепляет скриншот бага
2. Комментирует под скриншотом: "Воспроизводится на Chrome 120"
3. Разработчик отвечает: "Исправлю сегодня"
4. После фикса: "Готово, проверьте"

## Технические особенности

### База данных
```sql
comments
├── id (PK)
├── content
├── task_id (FK, nullable)      -- Комментарий к задаче
├── artifact_id (FK, nullable)  -- Комментарий к артефакту
├── author_id
└── created_at

Constraint: task_id XOR artifact_id (только одно из двух)
```

### API
```
GET  /api/comments/task/{taskId}         -- Комментарии задачи
GET  /api/comments/artifact/{artifactId} -- Комментарии артефакта
POST /api/comments                       -- Создать (taskId ИЛИ artifactId)
```

### Фронтенд состояние
```typescript
artifacts: Artifact[]                      // Список артефактов
artifactComments: Record<number, Comment[]> // Комментарии по ID артефакта
expandedArtifacts: Record<number, boolean>  // Развернут ли артефакт
newArtifactComment: Record<number, string>  // Текст нового комментария
```

## Преимущества

✅ **Контекстность** - комментарии привязаны к конкретному файлу
✅ **Удобство** - не нужно упоминать имя файла в комментарии
✅ **Организация** - легко найти обсуждение конкретного артефакта
✅ **Масштабируемость** - можно добавить реакции, упоминания и т.д.
✅ **Обратная совместимость** - старые комментарии к задачам работают
